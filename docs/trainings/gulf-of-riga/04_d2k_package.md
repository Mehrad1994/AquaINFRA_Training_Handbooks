## Key points

- A **D2KP** ties together everything needed to reproduce one analysis: the Secchi dataset, the HELCOM polygons, the Galaxy workflow, the source code, a virtual lab, and the docs.
- It exposes **four interaction levels** - you pick your door:

<div class="table-wrapper">
<table>
    <thead><tr><th>Door</th><th>For</th></tr></thead>
    <tbody>
        <tr><td><strong>Workflow + step-by-step guide</strong></td><td>Run the analysis in Galaxy without writing code (Chapter 7).</td></tr>
        <tr><td><strong>Virtual lab (MyBinder)</strong></td><td>Open RStudio with the code pre-loaded; edit and re-run live.</td></tr>
        <tr><td><strong>Web API (OGC)</strong></td><td>Drive the same processing from your own scripts/systems.</td></tr>
        <tr><td><strong>Reproducible basis</strong></td><td>The full toolbox + input datasets on GitHub/Zenodo, with DOIs.</td></tr>
    </tbody>
</table>
</div>

- Find it from any of its datasets via the AIP **"Related Content"** panel; everything is citable via a **Zenodo DOI**.

🔗 **Live D2KP**: <a href="https://aquainfra.dev.52north.org/result/zenodo:17175368" target="_blank" rel="noopener">Gulf of Riga D2KP on the AIP</a>

<details>
<summary><strong>Read more on the D2KP concept</strong></summary>

The method behind D2KPs is described in the open-access article *"Encouraging reusability of computational research through data-to-knowledge packages: a hydrological use case"* by the AquaINFRA team. The key idea: every component is a different **interaction level**, but all four doors produce the same canonical analysis.

</details>

---

## ✅ Key takeaways

- A D2KP is a **multi-modal reproducibility bundle**, not a zip of files - four doors, one canonical analysis.
- Pick the door that matches your skill level: run it, edit it, call it, or archive it.
- Cite via the **Zenodo DOI**.
